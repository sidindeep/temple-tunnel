## Исправленные проблемы

R1–R5 исправлены 22 сентября 2026 года. Регрессионные проверки добавлены в
`test/connection-lifecycle.test.js` и `test/singbox.test.js`; точные пути также
проверяются встроенным валидатором sing-box. Ниже сохранены исходные сценарии и
критерии, чтобы они оставались частью выпускного контракта.

### R1 · P1 · Смена стратегии удаляет разрешение TUN из Kill switch

**Сценарий:** VPN подключён, Kill switch включён, пользователь меняет «Авто» на
ручную стратегию. `settings:update` сохраняет работающий туннель, но вызывает
`armGuard()` без имени интерфейса. Значение по умолчанию — `-`.

**Основание:** `src/main.js:77`, `src/main.js:2022`, `src/main.js:2024`;
`tools/network-guard.cpp:100` и последующее условие `if (luid.Value)`.
Модуль WFP заменяет прежние фильтры и не создаёт разрешение интерфейса для `-`.
В синтетическом воспроизведении: статус `connected`, вызов `apply("-")`,
перезапуска TUN нет. Это создаёт риск блокировки пользовательских соединений
при сохраняющемся статусе «Подключено»; сетевое последствие требует packet-теста.

**Исправлено:** изменение только стратегии не заменяет WFP-фильтры; разрешение
активного интерфейса сохраняется.

**Готово, когда:** переключение auto/manual сохраняет и TUN, и его разрешение;
HTTP/DNS защищаемого приложения продолжают работать. Добавить регрессионный тест
с включённым Kill switch: существующий тест стратегии этого сочетания не покрывает.

### R2 · P1 · Обновление ядер отменяет ручную остановку VPN

**Сценарий:** VPN работал, начато обновление ядер, во время проверки нового
соединения пользователь нажал отключение. Обработчик воспринимает любой статус
кроме `connected` как неудачу обновления, откатывает ядра и снова запускает VPN.

**Основание:** `src/main.js:1774–1779`. `updateBusy` защищает только операции
обновления друг от друга. Синтетический вызов текущего обработчика дал цепочку
`stop → start → USER_STOP → stop → rollback → start`, итог — `connected`.

**Исправлено:** обновление отслеживает ручное отключение и прекращает фоновое
переподключение без отката успешно проверенного пакета.

**Готово, когда:** остановка на любом этапе обновления не приводит к позднему
подключению. Отдельно проверить обновление одновременно со сменой режима/подписки.

### R3 · P1 · При недоступном журнале обычный выход не снимает сессионную блокировку

**Сценарий:** создание зашифрованного журнала завершилось ошибкой, затем VPN
работает с Kill switch «Во время подключения и при сбое». При обычном выходе
ветка со снятием WFP выполняется только при наличии `fileLog` либо незавершённой
проверки сервера/задержки. Для установившегося соединения без журнала она пропускается.

**Основание:** `src/main.js:1725`, `src/main.js:2084–2098`. Проверка обработчика
`before-quit` с отсутствующим журналом не вызвала `networkGuard.clear()`.
Постоянные WFP-фильтры могут остаться после нормального закрытия приложения.

**Исправлено:** завершение туннеля и сессионной защиты выполняется независимо от
наличия зашифрованного журнала.

**Готово, когда:** нормальный выход снимает session-защиту и при ошибке журнала;
always-защита сохраняется; ошибка очистки имеет отдельный проверенный сценарий.

### R4 · P1 · Маршрутизация и Kill switch используют разную идентичность приложения

**Сценарий:** выбрано `C:\A\browser.exe`, а также запущено
`C:\B\browser.exe`. Для sing-box обе программы подходят под имя `browser.exe`,
но WFP защищает только точный путь `C:\A\browser.exe`.

**Основание:** `src/singbox.js:124–136`, `src/singbox.js:168`;
`src/network-guard.js:14–30`; `tools/network-guard.cpp:55–60`.
Генерация конфигураций подтвердила `process_name: ["browser.exe"]` для VPN
и единственный `--protect C:\A\browser.exe` для firewall.

**Следствие:** набор программ, отправляемых через VPN в selected-режиме, шире
набора защищённых при падении туннеля. Для второго пути возможен прямой выход;
это вывод из расхождения правил, фактическая утечка пакетов не измерялась.

**Исправлено:** выбранные EXE используют точный путь и остаются разными при
одинаковом имени файла. Совпадение только по имени сохраняется для записей без
пути, которые разрешены лишь при выключенном Kill switch. Дочерние процессы
по-прежнему требуют отдельного выбора и входят в матрицу натурной проверки.

**Готово, когда:** две программы с одинаковым именем, но разными путями имеют
однозначную и одинаковую трактовку во всех слоях, включая падение ядра.

### R5 · P2 · Переход «Всегда» → сессионная защита оставляет блокировку без VPN

**Сценарий:** VPN отключён, Kill switch установлен в «Всегда». Пользователь
меняет его на «Во время подключения и при сбое» и сохраняет настройки.
Очистка вызывается только для `off`; завершающая ветка повторно включает
защиту, поскольку `networkGuard.active` всё ещё истинен.

**Основание:** `src/main.js:1968–1975`, `src/main.js:2024`. Синтетическая проверка:
новая настройка `session`, вызов `apply("-")`, вызова `clear()` нет.

**Исправлено:** переход `always → session` при отключённом VPN очищает WFP-фильтры.

**Готово, когда:** выбранная политика и фактическая доступность сети согласованы;
проверены переходы off/session/always в connected/disconnected/error.

## Что обязательно проверить перед выпуском

### V1 · P1 · Проверка реальных пакетов на Windows

Документы `docs/0.14.0.md` и `docs/0.14.1.md` прямо ограничивают результаты:
WFP `validate` проверяет операции в отменяемой транзакции, а не защиту трафика.
Это открытый критерий готовности, а не доказанная утечка во всех режимах.

Нужен отдельный стенд/тестовый профиль с правами администратора и матрицей:

- full/selected/bypass × off/session/always;
- IPv4, IPv6, системный DNS, DNS приложения, TCP и UDP;
- нормальная работа, падение sing-box/Xray/UI, потеря сети, сон/пробуждение;
- ручная остановка, автоматическое восстановление, обновление и откат;
- второй VPN, два одинаковых имени EXE, дочерний процесс выбранной программы;
- нормальный выход, следующий запуск, перезагрузка Windows и удаление приложения.

Критерий: трафик защищаемого приложения не выходит напрямую в состояниях,
где включённая политика этого не допускает; разрешённые исключения и аварийное
снятие только правил Temple Tunnel работают. Сохранить обезличенные результаты.
