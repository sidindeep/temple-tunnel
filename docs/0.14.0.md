# Temple Tunnel 0.14.0

## Импорт

«Подписка → QR из картинки» открывает PNG/JPEG с компьютера. Камера и внешние
сервисы распознавания не используются. Поддерживаются светлые и инвертированные
QR-коды с HTTPS-подпиской, VLESS или Hysteria 2. На картинке должен быть один код.
Импорт заполняет скрытое поле: пользователь нажимает «Добавить» или «Сохранить».
Текстовые файлы TXT/CONF/LIST и вставка нескольких ключей также поддерживаются.
Повторы удаляются; количество пропущенных и неподдерживаемых строк показывается.
Пределы: файл 8 МиБ, изображение 24 Мп, импортируемый текст 256 КиБ.

## IPv6 и DNS

TUN получает IPv4 и IPv6. Политика «Блокировать» перехватывает IPv6 и отклоняет
его до правил прямого доступа. Политика «Передавать через туннель» применяет
обычные маршруты к IPv6. Это поведение при работающем TUN; системная защита
при его остановке задаётся отдельно через Kill switch.

DNS может следовать маршрутам или отправлять все публичные запросы через VPN.
Локальные имена остаются отдельным исключением. Собственный DoH приложения
является обычным HTTPS-трафиком и следует правилам этого приложения.
Диагностика проверяет TLS/DNS на локальном VPN-выходе и наличие IPv6-интерфейса;
она не выдаётся за доказательство отсутствия утечек конкретных приложений.

## Kill switch

Выключен по умолчанию. `network-guard.exe` создаёт постоянные WFP-фильтры для
IPv4/IPv6 в отдельном provider/sublayer. Замена фильтров выполняется транзакцией.
Ошибка транзакции оставляет предыдущие фильтры; ошибка включения защиты
прерывает запуск VPN. Правила переживают завершение интерфейса и VPN-ядра.

- Во время подключения и при сбое: включается перед подключением; отключается
  при ручном отключении или обычном завершении приложения.
- Всегда: остаётся после ручного отключения и закрытия приложения; снимается
  выбором «Выключен».
- Только выбранные: защищает указанные EXE-файлы. Если есть пользовательские
  маршруты «Через VPN», блокировка при отключении расширяется на весь компьютер.
- Все, кроме выбранных: указанные полные EXE-пути остаются разрешены.

Разрешены loopback, интерфейс текущего TUN, точные пути клиента и ядер, DHCP.
Windows DNS Client является общим для приложений: внешние DNS-запросы на порт
53 блокируются вне TUN, кроме разрешённых процессов. Поэтому без VPN новые
доменные соединения прямых приложений могут не работать. При активной защите
клиент использует Cloudflare DoH для начального разрешения адресов, а прямые
DNS-запросы ядра идут к системному IPv4 DNS-серверу непосредственно из ядра.

Защита ранней фазы загрузки Windows до запуска BFE не заявляется. Правила
по EXE не распространяются автоматически на другие вспомогательные процессы.

**Статус проверки:** модуль собран MSVC; модульные проверки порядка запуска,
ошибок, сохранения защиты при аварии и ручного отключения проходят. Применение
WFP и проверка реальных пакетов не выполнены: текущая сессия не имеет повышенных
прав (`ERROR_ACCESS_DENIED`), Windows Sandbox отсутствует. До испытания с правами
администратора эту сборку нельзя считать проверенной защитой от утечек.

Для аварийного снятия только правил Temple Tunnel из повышенной PowerShell:

```powershell
& 'C:\путь\к\Temple Tunnel\resources\bin\network-guard.exe' clear
```

Удаление приложения снимает его WFP-фильтры и требует прав администратора;
при ошибке снятия правил удаление прерывается. При обновлении постоянная
блокировка сохраняется. Команда `validate full - --allow C:\путь\app.exe`
проверяет WFP-операции в транзакции и всегда отменяет её, не включая фильтры.

## Подписанные обновления

Опубликованного сервера обновлений нет. «Журнал → Выбрать пакет обновления»
принимает локальный `update.json` и соседние файлы. Подпись Ed25519 проверяется
по встроенному публичному ключу, затем проверяются имена, размеры, SHA-256 и
диапазон совместимых версий. Скопированные файлы повторно проверяются.

Пакет приложения содержит `setup.exe`. Установщик запускается после подтверждения.
Импорт пакета уже установленной версии сохраняет его для будущего отката.
Откат приложения доступен после сохранения предыдущего подписанного установщика.
Это подпись манифеста выпуска; она не является Windows Authenticode-сертификатом.

Пакет ядер содержит `sing-box.exe` и `xray.exe`. Перед включением проверяются
вывод версии и конфигурация выбранного сервера без создания TUN. Версии хранятся
отдельно; указатель обновляется атомарно. При неподтверждённом переподключении
восстанавливаются прежние ядра. Ручной откат первой версии возвращает ядра
из установщика. Подпись и хеши активного пакета проверяются при запуске приложения.

Подписание выпуска выполняется локально:

```powershell
node tools/sign-update.js DIRECTORY app 0.14.0 0.13.10
node tools/sign-update.js DIRECTORY cores 0.14.0 0.14.0 0.14.0 1.13.20 26.3.27
```

Закрытый ключ находится вне проекта в `%LOCALAPPDATA%\TempleTunnelRelease`.
Он не входит в установщик. Для следующих выпусков нужно сохранить этот ключ;
повторно выполнять `--init` не следует.
