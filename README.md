# Temple Tunnel

Клиент для VLESS-подписок с раздельным туннелированием по приложениям. Основной
клиент работает на Windows; отдельный Android-клиент и APK описаны в
[документации Android](docs/android.md).

В версии 0.14.0 добавлены импорт QR из PNG/JPEG и списков ключей, политики
IPv6/DNS и подписанные локальные обновления с откатом. Реализация Kill switch
включена в сборку, но ещё требует проверки реальных пакетов с правами
администратора. Подробности и границы проверки: [0.14.0](docs/0.14.0.md).

## Возможности

- главная: поиск и выбор серверов, крупная кнопка подключения, выбор режима и тест пинга;
- «Управление подключением» разделено на вкладки «Приложения» и «Сайты-исключения» с просторными вертикальными списками и общей панелью режима; стратегия выбора сервера доступна на главной;
- импорт HTTPS-подписки или отдельного `vless://` ключа;
- несколько зашифрованных подписок с быстрым переключением, редактированием и удалением;
- VLESS с REALITY, TCP, XHTTP, gRPC, WebSocket, HTTPUpgrade и HTTP/2;
- три режима: весь трафик, только выбранные приложения, все кроме выбранных;
- по умолчанию — «Все, кроме выбранных»; сохранённый выбор режима сохраняется;
- отдельные сохранённые списки приложений для включения в VPN и исключения из VPN;
- ручное обновление задержки до серверов и сортировка списка от меньшего пинга к большему;
- проверка доступности полным TLS-рукопожатием без ложных ответов локального TUN-драйвера;
- российские IP-адреса и домены идут напрямую в двух раздельных режимах;
- доменное исключение с `www.` охватывает также адрес без `www.`;
- выбор приложений через диалог `.exe` или список процессов; при доступном пути маршрут и Kill switch используют точный EXE-файл;
- защищённое хранение подписки и серверных профилей через Windows `safeStorage`;
- проверка реального соединения с VPN-сервером перед показом статуса «Подключено»;
- режим «Авто»: до трёх параллельных проверок серверов через локальные прокси без создания TUN;
- бюджет подбора — 15 секунд, бюджет кандидата — 8 секунд; затем запускается и проверяется системный туннель;
- приоритет последнего рабочего сервера, история задержек и ошибок, временное исключение проблемных серверов;
- режим «Только выбранный сервер»: без автоматической замены; нажатие на сервер включает этот режим;
- автоматическое переключение на следующий сервер через 2 секунды при разрыве соединения;
- ручная остановка ожидающего автоматического переподключения из предупреждения;
- мгновенное принудительное отключение VPN по нажатию выключателя;
- безопасная отмена ещё не завершившегося подключения и защита от пересекающихся команд;
- защита от одновременного запуска нескольких копий приложения;
- автоматическая проверка конфигурации перед запуском sing-box;
- автоматический выбор свободной подсети TUN при одновременной работе с другим VPN;
- зашифрованный журнал этапов подключения с временем каждого этапа;
- экспорт очищенной текстовой копии через «Журнал → Экспорт журнала».

Журнал хранится в `%APPDATA%\temple-tunnel\logs`: AES-256-GCM, ключ защищён
Windows через Electron safeStorage (DPAPI). Незашифрованного резервного режима нет.
Запись выполняется асинхронно с буфером 250 мс. До четырёх файлов по 5 МиБ;
файлы без записей более 7 дней удаляются при запуске и записи; возраст определяется
по времени последней записи, поэтому активный журнал не теряется при старой дате
создания файла. Журнал отмечает причину приостановки туннеля и результат проверки
VPN перед автопереподключением. При тайм-ауте запуска VPN-ядра он сохраняет
состояние процесса, результат проверки локального порта и безопасную категорию
вывода ядра; если причина не распознана, это указано явно. При аварийном завершении
последние ещё не записанные сообщения могут потеряться. Сырые ответы API,
конфигурации и вывод VPN-ядер не сохраняются: ядра записывают только категории
ошибок. Экспорт — обычный текст, сохраняемый только по запросу пользователя.

Для XHTTP используется официальный Xray-core, а sing-box сохраняет системный TUN,
российские списки и правила раздельного туннелирования.

С версии 0.14.3 журнал подключения содержит версию клиента, сборку ОС,
архитектуру, параметры TUN без адресов, PID и коды завершения ядер,
источник и уровень сообщений. Ошибки TUN различают этапы создания адаптера,
настройки IPv4/IPv6, DNS, загрузки драйвера и WFP; сохраняются распознанная
причина и явно обозначенный системный код ошибки. Если причина неизвестна,
это указано явно. Пути, ключи, адреса серверов и сырой вывод ядер не сохраняются.
Для диагностики на другом ПК повторите подключение и выберите
«Журнал → Экспорт журнала».

С версии 0.14.5 прямой DNS фиксируется перед запуском TUN: выбирается IPv4 DNS
подключённого интерфейса с обычным маршрутом по умолчанию и наименьшей суммой
метрик маршрута и интерфейса. Собственные адаптеры Temple Tunnel исключаются.
Если определить DNS не удалось, используется прямой запрос к 1.1.1.1; источник
отмечается в журнале. Это действует и при выключенном Kill switch. Номер версии
в интерфейсе берётся из запущенного приложения.

В 0.14.6 исправлен запуск этого DNS на sing-box 1.13: прямой dialer используется
по умолчанию, без несовместимого `detour` на пустой прямой outbound. Проверка
включает реальный запуск ядра без TUN и личных профилей, дополнительно к `check`.

Установщик 0.14.6 автоматически закрывает запущенные версии Temple Tunnel
перед заменой файлов. Он запрашивает права администратора, отправляет штатное
закрытие и ждёт до 10 секунд. При зависании завершает дерево процессов клиента;
другие VPN-программы не закрываются. Если закрытие не удалось, установка
останавливается до замены файлов. Подписки и настройки сохраняются.

В 0.14.7 исправлен путь извлечения помощника закрытия: он запускается из
временной папки установщика. Проверка выполняет скомпилированный NSIS-код,
включая извлечение файла и запуск PowerShell, с именем приложения с пробелами.

С версии 0.14.4 Windows-настройка `DisabledComponents` проверяется перед
созданием TUN. Если системно отключён IPv6 на обычных интерфейсах (бит `0x10`,
включая значения `0xFF` и `0xFFFFFFFF`), клиент создаёт IPv4-туннель и использует
IPv4 для DNS. Настройки Windows не изменяются. До 0.14.10 `strict_route` оставался включённым;
при недоступной или некорректной системной настройке сохраняется обычный TUN
с IPv4 и IPv6. Политика «Блокировать IPv6» сама по себе не отключает его перехват.

Настройки Windows сохраняются в `%APPDATA%\temple-tunnel\settings.json`; перед
очередной записью последняя читаемая версия попадает в `settings.json.bak`.
Если основной файл не открывается или не расшифровывается, приложение сохраняет
его без изменений и блокирует дальнейшую запись. При наличии проверенной копии
на экране появляется действие «Восстановить настройки»: исходный файл будет
сохранён отдельно, после чего нужно проверить подписки и выбранный сервер.

## Автоматический подбор

В 0.14.10 исправлена совместная работа с другим VPN в раздельных режимах.
Добавление или удаление его адаптера запускает проверку нашего соединения:
исправный туннель продолжает работать; восстановление начинается после
подтверждённого сбоя за 10 секунд. Исключённые EXE обрабатываются до общего
перехвата DNS и IPv6. Выход sing-box, Xray и прямого DNS закрепляется за
подключённым физическим интерфейсом, чтобы второй VPN не становился транспортом
нашего ядра. Если физический выход определить не удалось, журнал отмечает
использование прежнего автоматического выбора.
Контрольные порты и SOCKS-мосты заранее проверяются для TCP и UDP: системный
резерв порта для одного протокола больше не приводит к выбору непригодного
номера для второго.

В раздельных режимах отключены глобальные DNS-фильтры `strict_route`, мешавшие
DNS другого VPN. Режим «Полная защита» сохраняет их. Они также сохраняются,
если IPv6 TUN отключён системно, но переходные интерфейсы IPv6 могут оставаться
включёнными (`DisabledComponents=0x10` или неизвестное значение). При полностью
отключённом IPv6 (`0x11`, `0xFF`, `0xFFFFFFFF`) раздельный режим совместим без
этих фильтров. Настройки Windows не меняются.

Для Kerio добавьте оба EXE: службу `kvpncsvc.exe` и интерфейс `kvpncgui.exe`.
Корпоративные маршруты к отдельным подсетям обслуживает сам Kerio. Два VPN,
которые оба принудительно забирают все системные маршруты, могут требовать
раздельного режима на стороне рабочего VPN. При включённом Kill switch общая
служба DNS Windows по-прежнему защищена от прямых запросов вне TUN; исключение
EXE не позволяет определить владельца запросов этой службы, поэтому работа
корпоративного DNS с этой настройкой требует отдельной проверки.

В режиме «Авто» сервер может быть выбран из любой страны активной подписки. Если важна конкретная
страна, выберите сервер вручную. Переключение между «Авто» и ручным режимом не перезапускает
исправный туннель. При автоматическом восстановлении резервный сервер также проходит подбор.

У последнего рабочего сервера без недавних ошибок есть фора 350 мс; при отсутствии свежей истории
или при восстановлении резервные проверки начинаются сразу. История хранится зашифрованно,
разделяется по подписке и видимой конфигурации сетевых интерфейсов, устаревает через сутки.
Изменения сети с прежними адресами интерфейсов могут не распознаваться. После двух сетевых ошибок
сервер временно исключается из автоматического подбора; ручная попытка остаётся доступной.

Диагностика сохраняет время этапов DNS, запуска локального прокси, защищённой проверки, запуска TUN
и итог подключения. Проверка успешного кандидата пока не переиспользует его процесс для TUN:
проверочные процессы завершаются, затем запускается основное ядро и подтверждается соединение.

Для проверки сохранённой подписки без изменения системной маршрутизации:

```powershell
npx electron tools/check-stored-selection.js
```

Проверка не меняет настройки; если включён другой VPN, результат зависит от его маршрутизации.

## Разработка

```powershell
pnpm install --frozen-lockfile
pnpm start
```

Для TUN нужны права администратора и `vendor/sing-box/sing-box.exe`. Собранный установщик автоматически запрашивает повышение прав.

В Git включены исходники, тесты, правила маршрутизации и исполняемые VPN-ядра,
необходимые для сборки. Личные подписки и настройки, кэш, результаты замеров,
промежуточные файлы и готовые установщики в репозиторий не входят. После
клонирования можно проверить код командой `node --test`, а установщик собрать
командой `pnpm dist`.

## Сборка установщика

```powershell
node --test
pnpm run build:guard
pnpm run build:core-host
pnpm dist
```

Готовый установщик появится в `artifacts/windows/`.
Логи проверок, пробы и снимки интерфейса хранятся отдельно в игнорируемой
папке `diagnostics/`. Папка `artifacts/` предназначена для результатов сборок
и локальных компонентов сборочного окружения, включая ключ Android-подписи.

## Android APK

Android-приложение находится в `android/` и собирается отдельно с JDK 17 и
Android SDK 35:

```powershell
cd android
.\gradlew.bat testDebugUnitTest assembleDebug
```

Инструкции по release-подписи: [packaging/android/README.md](packaging/android/README.md).

## Обновление установленной копии

После сборки `npm run pack` установленную копию можно обновить без переустановки:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\update-installed.ps1
```

Скрипт закрывает Temple Tunnel, заменяет файлы приложения и запускает его снова.
Пользовательские настройки и зашифрованная подписка хранятся отдельно и сохраняются.

## Особенности

- поддерживаются VLESS и Hysteria 2;
- подписки с HTTP-перенаправлением намеренно отклоняются, чтобы секретная ссылка не ушла на другой домен;
- в режиме «Полная защита» российские сайты также идут через VPN;
- в раздельных режимах DNS учитывает правила доменов и распознанных приложений; в режиме «Только выбранные» запросы общей службы DNS Windows идут через VPN, кроме доменных исключений, поскольку определить запросившее приложение по процессу службы нельзя;
- приложение не является продуктом Browsec или BlackTemple и не использует их код или графические материалы.
