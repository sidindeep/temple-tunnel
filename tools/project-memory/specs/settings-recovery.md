# Восстановление настроек Windows

## Контракт

- `settings.json` содержит нешифрованные флаги режимов и политик и
  зашифрованные поля подписок, маршрутов и истории подключения. Отсутствие
  файла означает первую установку; ошибка чтения, JSON или расшифровки не
  означает пустую подписку.
- После полной проверки загруженного файла приложение хранит его содержимое
  как последнюю корректную версию. Перед очередным сохранением эта версия
  атомарно записывается в `settings.json.bak`; затем новая версия записывается
  во временный файл и переименовывается в `settings.json`. При отказе переименования
  прямая перезапись файла не применяется.
- Если основной файл не читается, запись блокируется и пользователь видит
  предупреждение. Резервная копия доступна для восстановления только после
  успешной проверки JSON и всех зашифрованных полей.
- Восстановление выполняется по явному действию пользователя: неисправный
  исходный файл переименовывается в `settings.json.damaged-*`, проверенная
  копия ставится на его место. После повторной загрузки пользователь сверяет
  подписки и выбранный сервер.
- Зашифрованные данные не расшифровываются в диагностический журнал или
  проектные артефакты. Если расшифровка невозможна и у основного файла, и у
  копии, оба файла остаются на диске для ручного восстановления.

## Проверка

`test/settings-store.test.js` покрывает отказ переименования, сохранность
последней версии, обнаружение корректной копии, карантин повреждённого файла,
блокировку записи при ошибке расшифровки и повторную загрузку после восстановления.
`test/renderer-navigation.test.js` проверяет доступность кнопки восстановления.
