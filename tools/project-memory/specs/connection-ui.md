# Главная и управление подключением

Цель: быстрый выбор сервера и подключение на главной; подробные настройки
раздельного туннелирования на отдельной вкладке «Управление подключением».

- Главная открывается первой. Слева — серверы активной подписки и поиск по
  названию без учёта регистра; справа — режим, круглая кнопка VPN, состояние,
  выбранный сервер и тест пинга. Используется тёмная тема приложения.
- Режим по умолчанию — «Все, кроме выбранных» (`bypass`): применяется при
  отсутствии сохранённых настроек или некорректном значении режима. Ранее
  сохранённый допустимый выбор пользователя сохраняется после перезапуска.
- Поиск фильтрует только отображение главной, не меняет выбор и не затрагивает
  настройки подключения. Пустая подписка и отсутствие совпадений
  имеют разные сообщения. Кнопка «Мои подписки» открывает управление подписками.
- Вкладка управления содержит списки приложений, исключения и параметры режима.
  Серверы, автоматическая/ручная стратегия и кнопка VPN находятся только на главной.
  При полной защите вместо списка показано пояснение о защите всех приложений.
- Обе вкладки отображают единое состояние основного процесса. Выбор сервера,
  переключение режима, подключение/отмена/отключение и тест пинга используют
  существующие IPC-действия. Поиск не хранится в пользовательских настройках.
- Тест пинга проверяет список серверов, как прежняя кнопка обновления задержек.
- Кнопка подключения учитывает ограничения, включая необходимость
  выбранных приложений в соответствующем режиме. Отмена подключения остаётся
  доступной во время соединения. Ошибки и предупреждения с остановкой
  восстановления видны независимо от открытой вкладки.

Исходники: `src/renderer/index.html`, `app.js`, `styles.css`.
Проверка событий и синхронизации: `test/renderer-navigation.test.js`.
Модульный тест использует адаптер DOM и имитацию IPC.
2026-09-18: в упакованном клиенте проверено отсутствие удалённых элементов;
реальное подключение в режиме bypass подтвердило защищённое соединение и DNS.

## Завершение проверочных процессов

После выбора рабочего сервера приложение ждёт завершения временных прокси
до пяти секунд: на Windows прежнего лимита в одну секунду могло не хватать,
что прерывало подключение с ENGINE_FAILED после успешной TLS-проверки.
Если процесс не завершён, запуск TUN по-прежнему блокируется. Этот случай
покрывает тест с отложенным событием завершения в `test/server-probe.test.js`.
При ошибке подключения убирается сообщение о проверке кандидата; ошибки TUN
показывают безопасную категорию диагностики без сырого вывода ядра.

## Быстрые исключения

Статус: реализовано. Проверено 2026-09-27 по `src/routing-settings.js`,
`src/singbox.js` и `test/routing-settings.test.js`; проверка реальных пакетов
на Windows с браузерным DoH ещё требуется.

В режиме раздельного туннелирования на вкладке управления подключением доступны
два быстрых действия: список уникальных `.exe` из Windows Task Manager
(`tasklist.exe`) и поле доменного исключения. При выборе процесса его PID и имя
повторно проверяются через Windows CIM, а полный путь EXE берётся из процесса
или связанной службы. Этот путь сохраняется для маршрута и WFP; если Windows
не выдаёт его, при включённом Kill switch выбор требует ручного указания EXE.
Ранее сохранённая запись только с именем заменяется записью с путём при повторном
выборе процесса или файла. При запуске с включённым Kill switch доступные
запущенные процессы из старых записей обновляются автоматически; недоступный
путь остаётся без изменений и требует выбора EXE. Домен сохраняется в
`customRouting.direct`, поэтому он и его поддомены идут напрямую во всех
режимах. Запись с начальным `www.` охватывает также домен без `www.`; правило
применяется и к DNS, а сопоставление ответов DNS с IP помогает маршрутизировать
соединения, где имя домена не удалось определить из трафика. Это не гарантирует
совпадения для DNS, который браузер отправил в обход системного резолвера.
При активном VPN изменение переподключает туннель. Kill switch требует
добавления EXE-файла с путём, потому что одного имени процесса недостаточно для
правила системного firewall.

Кнопка «Диспетчер задач» открывает отдельное модальное окно Electron со списком
процессов, поиском и обновлением. Список прокручивается в пределах этого окна
и не зависит от высоты панели управления подключением. Выбор добавляет процесс
в активный список приложений и закрывает окно; закрытие без выбора не меняет
список. Ошибка загрузки или добавления показывается в окне, которое остаётся
открытым для повторной попытки.

При выборе EXE маршрут приложения и Kill switch используют один полный путь.
Одинаковые имена файлов в разных каталогах считаются разными приложениями.
Добавление только по имени остаётся доступным при выключенном Kill switch,
если Windows не раскрывает путь процесса.

Ручное отключение имеет приоритет над фоновым переподключением при обновлении
ядер. Смена только стратегии «Авто»/«Только выбранный сервер» сохраняет текущий
туннель и его WFP-разрешение.
Ручное отключение также отменяет поздний запуск после сохранения настроек,
изменения приложений, маршрутов или активной подписки. Удаление последней
подписки завершает сессию и снимает сессионный Kill switch.

Если файл настроек не читается, интерфейс показывает предупреждение и
блокирует сохранение поверх него. При наличии проверенной резервной копии
доступна кнопка восстановления с подтверждением. Нечитаемый исходный файл
сохраняется отдельно; после восстановления пользователь проверяет подписки и
выбор сервера.

## Диагностика переподключения

Зашифрованный журнал Windows хранит этапы подключения и причины остановки
туннеля. Перед остановкой из-за смены сетевых интерфейсов, отсутствия сети
или сна компьютера записывается безопасная категория события без адресов
интерфейсов. При неудачной контрольной проверке журнал фиксирует область
сбоя (DNS или HTTPS) и исход (тайм-аут или ошибка); автопереключение следует
только после повторных проверок в течение 10 секунд. Отключение кнопкой VPN
отмечается отдельно. Неожиданное завершение VPN-ядра или Xray фиксируется с
кодом выхода. Повторное подключение после смены сети и переключение
сервера различаются в этапах подключения.

Если локальный порт ядра не открылся до тайм-аута, журнал фиксирует имя ядра,
длительность ожидания, состояние процесса, категорию последней ошибки проверки
порта, число строк stdout/stderr и последнюю распознанную категорию вывода ядра.
Сырые строки, адреса и номер локального порта в эту сводку не попадают. Если ядро
не дало распознанной причины, журнал сообщает об этом явно; категория отказа
локальная и не запускает переключение сервера.

Активный файл журнала сохраняется, пока его время последней записи моложе
семи дней, независимо от времени создания файла в Windows. Старые записи
исключаются из текстового экспорта; ограничение размера и ротация файлов
остаются действующими. Сырые ответы VPN-ядер, конфигурации и сетевые адреса
в диагностические сообщения не попадают.
